# Dynamic Endpoints

A dynamic endpoint is one whose URL depends on a value only known at call time — an ID in the path, a search term in a query string, and so on. Instead of a fixed `url` string, you register a `url` function and a `params` type.

## Registering a dynamic endpoint

```ts
// types.ts
export interface User {
  id: number;
  name: string;
}

export interface UserByIdParams {
  id: number;
}
```

```ts
// api.ts
import { register } from "your-lib-name";
import type { User, UserByIdParams } from "./types";
import { UserSchema } from "./schemas";

const BASE_URL = "http://localhost:3001/api";

export const api = register<{
  userById: { type: User; params: UserByIdParams };
}>({
  userById: {
    url: (params) => `${BASE_URL}/user/${params.id}`,
    schema: UserSchema,
  },
});

export const useFetch = api.useFetch;
```

The `url` field is now a function of `params` instead of a plain string. TypeScript infers `params`'s shape from the `params` field you declared in the type map, so the function signature is checked automatically — get the shape wrong and it won't compile.

## Consuming it

`useFetch` accepts the params as a second argument whenever the registered state declares one:

```tsx
function UserProfile({ userId }: { userId: number }) {
  const { data: user, isLoading, error } = useFetch("userById", { id: userId });

  if (isLoading) return <p>Loading...</p>;
  if (error) return <p>{error.message}</p>;

  return <p>{user?.name}</p>;
}
```

## Query parameters work the same way

Path and query parameters are both just string interpolation inside your `url` function — there's no separate API for them.

```ts
export interface SearchParams {
  query: string;
}

export const api = register<{
  searchUsers: { type: User[]; params: SearchParams };
}>({
  searchUsers: {
    url: (params) => `${BASE_URL}/user/search?q=${encodeURIComponent(params.query)}`,
    schema: UsersSchema,
  },
});
```

```tsx
const { data: results } = useFetch("searchUsers", { query: searchTerm });
```

## Caching behavior with parameters

Dynamic endpoints are cached per unique combination of state name and params — `useFetch("userById", { id: 1 })` and `useFetch("userById", { id: 2 })` are treated as separate cache entries, but two components both calling `useFetch("userById", { id: 1 })` share the same request.
