# OData Endpoints

Some backends (especially .NET APIs) expose OData-style query support: `$filter`, `$orderby`, `$top`, and `$skip` as query string conventions for filtering, sorting, and paging server-side. Since this library doesn't care what your backend is written in, wiring up OData support is just a matter of building the right query string in your `url` function.

## Defining the OData query shape

```ts
// types.ts
export interface ODataQuery {
  filter?: string;
  orderBy?: string;
  top?: number;
  skip?: number;
}

export interface Movie {
  id: number;
  title: string;
  year: number;
}
```

## A small helper to build the query string

Keeping this in one place means every OData-backed endpoint builds its query string the same way.

```ts
// odata.ts
import type { ODataQuery } from "./types";

export function buildODataQuery(query: ODataQuery): string {
  const params = new URLSearchParams();

  if (query.filter) params.set("$filter", query.filter);
  if (query.orderBy) params.set("$orderby", query.orderBy);
  if (query.top !== undefined) params.set("$top", String(query.top));
  if (query.skip !== undefined) params.set("$skip", String(query.skip));

  return params.toString();
}
```

## Registering the endpoint

```ts
// api.ts
import { register } from "your-lib-name";
import type { Movie, ODataQuery } from "./types";
import { MoviesSchema } from "./schemas";
import { buildODataQuery } from "./odata";

const BASE_URL = "http://localhost:3001/api";

export const api = register<{
  moviesOData: { type: Movie[]; params: ODataQuery };
}>({
  moviesOData: {
    url: (params) => `${BASE_URL}/movies?${buildODataQuery(params)}`,
    schema: MoviesSchema,
  },
});

export const useFetch = api.useFetch;
```

## Consuming it

```tsx
function RecentMovies() {
  const { data: movies, isLoading, error } = useFetch("moviesOData", {
    filter: "year gt 2010",
    orderBy: "year desc",
    top: 10,
  });

  if (isLoading) return <p>Loading...</p>;
  if (error) return <p>{error.message}</p>;

  return (
    <ul>
      {movies?.map((movie) => (
        <li key={movie.id}>{movie.title} ({movie.year})</li>
      ))}
    </ul>
  );
}
```

This produces a request to:

```
GET /api/movies?$filter=year%20gt%202010&$orderby=year%20desc&$top=10
```

## Combining OData with pagination

`$top` and `$skip` are OData's native pagination mechanism, so an OData endpoint typically doesn't need the separate `page`/`pageSize` pattern from [Paginated Endpoints](./paginated-endpoints) — `$skip` (offset) and `$top` (page size) cover the same need directly in the query string.

## A note on trust boundaries

Since `filter` and `orderBy` are raw strings passed straight into the query, make sure any user-supplied search input is validated or sanitized before being placed into `filter` — the library validates the *response* shape against your schema, but it doesn't sanitize *outgoing* query values for you.
